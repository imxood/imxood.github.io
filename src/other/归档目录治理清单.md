# 归档目录治理清单

## 说明

- 本清单用于记录历史样例目录的保留策略与迁出评估.
- 目标不是删除所有样例, 而是让样例目录不再干扰正式知识导航.

## 已确认的归档目录

### `program/web/`

- 角色: 历史 Web 示例工程归档.
- 当前子目录: `react/`, `vue/`, `js/`, `vite-svelte/`.
- 处理结论: 保留在主知识树内, 但通过 `program/web/README.md` 统一承接.
- 备注: 不再把下层项目 README 大量挂入 `SUMMARY`.

### `program/rust/code/`

- 角色: Rust 实验工程与技术验证归档.
- 处理结论: 保留在主知识树内, 通过 `program/rust/code/README.md` 承接.
- 备注: 只保留上层入口进入主导航, 深层样例不再继续展开到 `SUMMARY`.

### `program/rust/test_usb/`

- 角色: USB 方向早期实验目录.
- 处理结论: 已补 `README.md`, 由 `rusb` 文档回链承接.
- 备注: 当前列为低优先级迁出候选, 暂不做物理迁移.

### `program/c_c++/qt/MXSpice/`

- 角色: Qt + ngspice 历史实验工程归档.
- 处理结论: 保留在主知识树内, 通过 `MXSpice/README.md` 承接.
- 备注: 不作为主知识入口, 只保留工程结构参考价值.

## 第一批低优先级迁出候选

- `program/web/js/`: 更偏素材和零散脚本归档.
- `program/web/vite-svelte/`: 更偏早期脚手架快照.
- `program/web/react/react-app/`: 更偏 `CRA` 时代模板归档.
- `program/rust/code/fonts/`: 更偏资源归档.
- `program/rust/code/svelte-web/`: 更偏前端 + 桌面混合实验归档.
- `program/rust/test_usb/`: 更偏早期 USB 验证快照.

## 本轮已执行的收敛动作

- 为 `program/rust/test_usb/` 补齐最小 `README.md` 入口, 避免裸目录无说明.
- 为 `program/web/react/react-demo/wasm-test/` 补齐最小 `README.md` 入口, 避免深层实验目录无说明.
- 在 `program/web/`, `program/web/react/`, `program/rust/code/` 上层入口中明确这批目录的归档角色.
- 将候选目录统一降级为低优先级归档说明页, 不再提升导航权重.
- 暂不执行物理迁移, 以保留历史可追溯性和现有路径稳定性.

## 保留在主知识树内的理由

- 样例工程仍然具有结构参考价值.
- 部分目录仍承载运行记录与集成思路线索.
- 当前更大的问题是导航噪音, 已通过归档说明页显著缓解.

## 长期迁出候选

### 第一组

- `program/rust/code/*` 中长期无维护, 仅保留最小样例价值的目录.
- `program/web/react/*`, `program/web/vue/*` 中纯脚手架模板型项目.
- `program/web/js/` 与 `program/web/vite-svelte/` 这类更偏素材或旧模板快照的目录.

### 第二组

- `program/c_c++/qt/MXSpice/` 若未来确认只保留历史快照意义, 可继续评估迁出主知识树.

## 当前阶段结论

- 本轮已完成归档目录统一入口化.
- 本轮补完了第一批候选目录的轻量说明和上层承接关系.
- 当前仍不执行大规模迁出, 以免破坏历史可追溯性.
- 后续若仓库体积, 导航复杂度或维护成本继续上升, 再启动第二阶段迁出评估.
