## 一级目录边界结论

### `frontend` 与 `program/web`

- `frontend/` 承接正式前端知识文档.
- `program/web/` 保留历史示例工程与迁移记录说明.
- 当前不建议把 `program/web/` 再合并回 `frontend/`, 避免样例工程污染主知识导航.

### `embedded` 与 `hardware`

- `embedded/` 承接 MCU, SoC, 调试链, 协议, 驱动与板级应用.
- `hardware/` 承接基础器件, 设备档案, 拆解记录与评测观察.
- `红米note4拆解` 已归入 `hardware/设备/`, `embedded/` 侧旧路径已完成内部清理.

### `tools` 与 `program`

- `tools/` 承接系统工具, 构建链, 运维工具, AI 工具和环境配置.
- `program/` 承接语言本体, 运行时, FFI 与跨语言交互.
- 当前边界整体稳定, 暂无高置信正式知识页需要从 `tools/` 与 `program/` 之间再次迁移.

## 深层目录治理结论

- `embedded/模块/` 与 `embedded/电路/` 适合保留子目录, 但由上层总览页承接导航.
- `embedded/stm32f103_bluepill/` 适合作为特定开发板实验目录, 不再直接散落到 `embedded/` 根层.
- `program/rust/code/` 与 `program/web/*` 保留为归档目录, 通过 `README.md` 统一承接.
- `program/c_c++/qt/MXSpice/` 保留为历史工程归档目录, 不进入主导航主干.

## 物理迁移结论

### 已确认完成的迁移

- `embedded/红米note4拆解.md` -> `hardware/设备/红米note4拆解.md`, 旧路径兼容页已在内部引用清理后删除.
- `hardware/Arduino.md` -> `embedded/arduino.md`, 旧路径兼容页已在内部引用清理后删除.
- `program/web/react/react.md`, `program/web/vue/vue.md`, `program/web/web.md` 的兼容页已清理, 主知识统一回收至 `frontend/`.

### 当前未继续执行物理迁移的原因

- 当前剩余高频问题更偏“角色不清”和“目录缺入口”, 而不是高置信错位.
- 进一步物理迁移的收益低于“补总览页 + 收敛导航 + 维持兼容路径”的收益.

## 当前状态判断

- 一级目录边界已基本稳定.
- 二级目录入口已明显改善.
- 后续更高收益的工作应转向 `embedded` 内部子主题层级收敛, 而不是继续大范围移动文件.
