# 知识库维护机制

## 说明

- 本文档用于固化知识库后续新增, 修改和整理时的统一流程.
- 目标是让知识库治理从“临时决定”升级为“稳定机制”.

## 新增文档时必须先判断角色

- `总览页`: 目录入口页, 承接阅读路径与子主题导航.
- `专题页`: 面向检索和学习的正式知识页.
- `归档页`: 样例工程, 历史记录, 实验上下文.
- `兼容页`: 旧路径说明页, 只保留跳转说明.

## 导航决策规则

- 正式知识页不一定自动进入 `SUMMARY`, 但必须有明确入口.
- 目录总览页通常应进入 `SUMMARY` 或上层总览页.
- 归档页优先通过上层归档入口间接访问.
- 兼容页不进入主导航.

## 批次整理规则

1. 先确定本批目录范围.
2. 先读上下文与父级总览页.
3. 再决定是 `补写`, `合并`, `移动`, `归档`, 还是 `兼容保留`.
4. 每批结束后必须刷新治理文档.
5. 每批结束后必须执行 `mdbook build`.

## 治理文档更新规则

每一轮整理后, 至少同步检查:

- `other/知识库总索引.md`
- `other/知识库整理清单.md`
- `other/知识库分类清单.md`
- 如涉及结构治理, 还要同步 `目录层级治理清单`, `归档目录治理清单`, `兼容页审计清单`

## 迁移与兼容规则

- 物理迁移文档时, 优先保留旧路径兼容页.
- 兼容页只保留最小说明, 不继续扩写旧内容.
- 当仓库内与导航中的引用清理完毕后, 才进入删除候选.

## 长期验收标准

- `SUMMARY` 持续保持 `0` 失效链接.
- 正式知识页有明确入口.
- 归档目录不干扰主导航.
- 未直接收录文档全部有解释.
- 新文档不再随意落到错误目录.

## 与 TODO 的关系

- `TODO.md` 是长期治理主计划.
- 本文档是执行层面的维护机制.
- 后续整理应优先遵循这两份文档, 而不是零散口头规则.
